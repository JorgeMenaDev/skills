# v5.0.1 lease-bootstrap patch — 2026-07-13

## Why

The first live initialization under matias#119 exposed a contract contradiction: the v5 lease had to exist before any workspace mutation, but all seven registered workspaces lacked the parent `loops/` directory. No helper defined the bootstrap exception or interoperable lease fields.

## Change

- Added `scripts/site-lease.mjs` with `status`, `acquire`, `renew`, and `release`.
- Defined the empty real `loops/` directory as the sole pre-lease bootstrap exception; exclusive `site-lease.json` creation still selects one writer.
- Serialized renew, release, and stale recovery through `site-lease.recovery.lock`.
- Required owner/run identity, positive-integer TTL minutes, RFC 3339 UTC timestamps, fail-closed malformed/expired handling, and real-file/directory paths.
- Kept cadence, coverage, obligations, ship events, and certificates operator-seeded from real evidence only.

## Manual lifecycle validation

No test files were added or modified, per repository policy. The helper was exercised in temporary workspaces:

| Case | Result |
| --- | --- |
| Cold status before `loops/` | `free`, `initialized: false` |
| First acquire | Created real `loops/`; exclusive lease acquired |
| Concurrent acquire | Exit 2, blocked on live owner |
| Matching renew | Atomic replacement succeeded |
| Existing recovery lock | Renew exited 2, blocked without lease mutation |
| Valid expired claim | Status `expired_claim`; renew blocked; matching owner release succeeded |
| Symlinked `loops/` | Exit 1, refused path |
| Wrong-owner release | Exit 1, refused mutation |
