## Design notes recorded at implementation

- **Stamp location.** The stamp lives at each resolved site workspace root (`<workspace>/reconciliation.json` — per-site in hub mode), outside `loops/` deliberately: `scripts/cadence-status.mjs` parses every non-reserved `loops/*.json` as loop state, so an in-loops stamp would have failed closed on every read or forced a script change. The reference documents this placement rationale. No script changes ship; drift detection and certificate blocking are prose contracts on the sessions that mint certificates, like the rest of the sleep-certificate discipline.
- **Autoreview hardening (same-day).** The Codex branch review (gpt-5.6-sol, thinking high) raised three findings, all confirmed and fixed pre-merge: per-workspace stamp scoping in hub mode (one shared stamp could have let one site's recap unmark six siblings), an absence/storage contradiction with the Optional schema-1 state section (carved out explicitly), and meaningless first recaps for workspaces freshly created by the current version (created-by equality is now reconciled-by-construction). The re-review raised one residual P2 — the fresh-workspace exemption leaned on the hub-global created-by version, false-drifting sites added to an already-upgraded hub — fixed by making creation-time stamping explicit (the creating run writes the new workspace's stamp in the same pass; only workspace-scoped created-by provenance ever substitutes). Round three asked for the creation-time contract to be mechanically implemented rather than session-owned prose: `bootstrap-seo-workspace.mjs` now writes `reconciliation.json` (`report: null`) on every workspace create path — deliberately not added to `GENERATED_WORKSPACE_FILES`, so the doctor never proposes it as a repair and existing stamp-less workspaces keep their drift semantics. Round four hardened the bootstrap seeding: the stamp is written only on a true create (allowlist-null path) so no repair or rerun can ever mark an existing stamp-less workspace reconciled — live-verified (fresh create stamps 5.2.0; a rerun against an existing workspace refuses with "create requires an absent target" and writes nothing). The clean re-review after the fixes is the merge evidence.
- **Templates row check** (map fog item): `templates/local-seo-gbp.md` already carries the factual + eligibility confirmation contract rows the guard relies on — no new rows needed for #125. #126 routes into the existing dated-report fields — no template exists or is needed. #133 adds `templates/upgrade-recap.md`.
- **Consumer effect.** On refresh, all registered hub workspaces (seven in the Matias hub) correctly surface as drifted (stamp absent = never reconciled) and cannot certify sleep until their first recap — the intended fail-closed introduction. Other eligible work continues.
