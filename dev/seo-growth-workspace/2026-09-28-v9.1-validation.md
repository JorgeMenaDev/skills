Baseline: 9.0.0 (`9f5375f`, unchanged at `8ca49f9`). Candidate: `1b28489`, then review fixes `37be68a`, `176c61a`, `45d1906` `0af1379` and `dd3051c`, final boundary rule `3800e7d`. - `node dev/seo-growth-workspace/check-skill.mjs`: 197 checks pass. The four new checks are the new links; no script or fixture changed.

## Behavior replay

Same request and constraints as the 9.0.0 comparison, run offline in fresh contexts with only the applicable skill. Frozen consumer packets from Matias `69049b725`: a growth SaaS with live bets and a content-engine queue, a local rental business with a measurable outcome path, and a site under an explicit no-new-pages mandate. The synthetic local held-out case was also included. Private packets and outputs stay in the consumer's Second Brain.

Grok 4.6 ran both versions on all four cases, through the grok CLI, because the consumer's surviving scheduled review uses it (in the Hermes harness, not this CLI). Claude Opus 5.5 subagents, the interactive model, ran both versions on the three site cases.

| Behavior | 9.0.0 | 9.1.0 at `1b28489` |
| --- | --- | --- |
| Each chosen bet names a finished state | 0 of 5 runs that chose a bet | 6 of 6 runs that chose a bet |
| Approval-boundary proposal | None | Growth SaaS and local rental on both models, where earlier packages waited on the same approval. None on the maintenance case. The held-out run declined because it was the first package of its kind |
| No-new-pages mandate | Respected on both models | Respected on both models |
| Package content | Drafts, exact revisions and messages on both models | The same depth, now labelled with state, location, gate and owner |
| Review length | Baseline | Shorter in 5 of 7 pairs |

Other observations:

- Finished states worked on both sides of an offline limit. When page files were unreadable, runs shipped exact replacement text plus the search that applies it, and named the gate.
- A content error in a frozen draft (a title suffix the site already appends) was repeated by both versions on Grok and caught by both on Opus. This is a quality difference between models, not between versions.
- Timing: Grok runs took 7–20 minutes per site and about 7 per held-out case, similar across versions. Opus runs took 13–23 minutes.

## Limits

This is a small replay on saved inputs, not a ranking or revenue test. The grok CLI is not the consumer's scheduled harness. Offline runs cannot show live execution. The unchanged specialist routes were not exercised.
