# v9.4.0 validation, 2026-10-08

Change: `content-engine-webhooks.md` steps 5 and 6. The calendar is built from DataForSEO data in a fixed order: pool audit, buyer-word suggestions, live results, gates. The engine is operated only through its CLI. Also new: SuperaSEO CLI 0.3.0 commands and `demand.mjs --suggest`.

## Structural

`node dev/seo-growth-workspace/check-skill.mjs`: 201 checks pass. The 2 new checks cover the `--suggest` dry run and the one-seed limit.

## Behavioural comparison

- **Case:** a held-out case drawn from a live site (Acredix, Chile, Spanish). Request: "the engine calendar produces posts with no traffic; remove it and make a new one with keywords that make sense".
- **Inputs:** a frozen packet in the consumer's private store with the engine pool export (418 keywords), the planned calendar (30 rows), `context.md`, Google Ads volumes for the pool, 34 Labs suggestion responses and 20 live result pages. The README was neutral: no CLI verbs or skill wording.
- **Runs:** one fresh agent per version (v9.3.1 at HEAD, v9.4.0 in the working tree), dry run, no network, writes only to scratch.
- **Model:** Claude Opus 5.5, the model of the consumer's interactive runs.

| Criterion | v9.3.1 | v9.4.0 |
| --- | --- | --- |
| Audits the whole pool for volume | yes (15 of 323) | yes (15 of 323) |
| Rejects the old calendar on evidence | yes (0 of 30 with volume) | yes (0 of 30) |
| Every scheduled row has reported volume, buyer fit and a checked result page | partly: 3 checked rows plus 3 unchecked "Phase B" rows on the calendar | yes: 4 checked rows; unchecked rows held behind a live check |
| Names the page each row feeds | by role | by page type, with CTA |
| Operates the engine through the CLI | no: falls back to the dashboard for adding keywords and rows | yes: `keywords add`, `calendar add`, `projects config get|set`; backend and deploy keys excluded |
| Keeps authority boundaries | yes | yes; holds the config change for owner approval |

Failure found and fixed: the v9.4.0 agent read "own-document-download results are a no" as covering results led by Studocu templates. It rejected two DS 44 queries whose results are weak document-sharing pages. The line now names certificate look-ups as the no-go, and calls document-sharing results winnable competition. That fix was not replayed.

Limits: one case, one model, one run per version. This is evidence about this behaviour, not general reliability. The standing three-case set was not replayed: this release changes only the content-engine reference, which the standing review cases do not exercise.
