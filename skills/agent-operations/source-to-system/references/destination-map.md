# Destination Map

Inspect plausible owners; route by authority, not convenience.

| Destination | Use when the source reveals | Typical durable owner |
|---|---|---|
| Product repository | Missing behavior, data model, UX, integration, security, performance, or observability | Repository that ships the behavior |
| Product or content engine | Missing operational state, revision evidence, workflow automation, or provider integration | System that executes and stores the workflow |
| Existing skill | An existing reusable process or guardrail is incomplete | Canonical source of that skill |
| New skill | A distinct leading word and recurring process need independent invocation | Configured skill source repository |
| Go-to-market system | Positioning, audience, channel, sales, pricing, lifecycle, or measurement should change | Company or project strategy and experiment tracker |
| Organization operations | Finance, compliance, hiring, partnerships, support, or administration should change | Operational tracker and evidence owner |
| Personal action system | Personal advice implies a decision or action | Existing personal tracker, plan, or reminder system |
| Knowledge base | Durable knowledge, an entity, decision, synthesis, or reusable context appears | Configured knowledge system |
| Provider or admin surface | Account configuration, hosting, analytics, billing, or marketplace state should change | Provider plus the workspace's evidence trail |
| No change | The idea is covered, unsupported, harmful, obsolete, or lower leverage | Review record only |

## Ownership graph

When several systems participate, order them and assign each state once:

```text
portable rule -> executing system -> rendered outcome -> measurement -> coordination record
```

## Selection

Compare decision or execution leverage, evidence strength, recurrence, current priorities, cost, reversibility, safety exposure, and measurable outcome. Select one coherent improvement per run. Keep alternatives as rejected or deferred, not as extra work.

Use the workspace's own execution lanes and approval rules; this skill does not override them.
