# Examples

## External tactic

**Input:** A video claims a new search tactic doubles traffic.

- Capture the full claim and supporting study.
- Classify the metric as marketing until primary data supports it.
- Compare it with the existing growth process and current product evidence.
- Recommend one bounded experiment with a metric and stop rule, or `NO_CHANGE`.

## Open-source tool

**Input:** A post promotes a repository as a drop-in automation layer.

- Pin and inspect the repository without running it.
- Separate the useful mechanism from the dependency's trust and maintenance cost.
- Prefer a small independent implementation when the mechanism is narrow and the dependency is unjustified.
- Require isolated runtime proof before adoption.

## Personal advice

**Input:** An article recommends a new personal productivity system.

- Read the user's existing knowledge and action systems first.
- Route durable knowledge, decisions, and executable actions to their existing owners.
- Prefer amending one existing system; often the correct disposition is `COVERED` or `SKIP`.

## Batch

Test the process on three to five sources before bulk review. Keep source reports separate until every report exists, then deduplicate recommendations and select one improvement for the run. A multi-project portfolio is a separate planning decision.

## Routing contrast

- Weak: “Create a new skill for this idea.”
- Strong: “The existing review skill owns the reusable rule; the product owns runtime state; one tracker item coordinates the verified gap.”
